# USER.md — 我在帮谁

## 基本

- **称呼**：«怎么称呼；有没有禁用词»
- **身份**：«职业 / 定位»
- **技术边界**：«他读不读代码？有没有明确不碰的东西？»
- **核心诉求**：«3 个词，例如 简单 / 低冗余 / 易维护»
- **远期愿景**：«一句话»

## 交付判据

«这一节最重要：写清「做到什么算成功」。判据要落在**可观察的结果**上，不要写成「他用得上」这类替他设阈值的说法。»

## 怎么配合（最常违反的几条）

1. **他读叙述，不读代码。** 任何「完成 / 通过 / 干净」的声明，都要附【可跑命令 + 可观察结果 + 负控制】。**只能绿不能红 ＝ 假绿。**
2. **结论先行**：先给判定，再展开论证。
3. «成本 / 时间敏感度：要不要先估成本？»
4. **动手前先出计划 + 逐项 TODO**；危险动作（启停 / 登录 / 删改 / 改配置）先复述理解、显式确认。
5. **短口令体系**：«他有哪些口令，各是什么意思»。**非口令的话是插叙或新任务** —— 别自行改写他的意思。

## 环境

- «机器 / 系统；哪台常驻做什么»
- «记忆分层放在哪»
- «还有哪些搭子»

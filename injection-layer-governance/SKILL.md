# 注入层治理

> **一句话**：把「记忆 / 规则 / 身份 / 目录」这些**每轮开局自动塞进模型上下文**的对象，管成永不越线；越线前先报警，而不是等它坏了再救。

---

## 0. 何时用 / 何时不用

**用**：**新机器 / 新容器第一次配注入层**（→ §5 首装）· 体检一组容器的注入体量 · 某个记忆文件已到上限 · 想把一段内容放进"正确的位置" · 换一台机器要搬记忆与身份 · 出现截断/被忽略的迹象要归因。

**不用**：
- 只是**重命名/删文件**级别的整理 → 那是文件管理，不是注入层治理。
- 容器**数量**层面的收口（归档退役 workspace）→ 另一条流程（workspace 归档）。
- skill 本身的使用度瘦身 → 那是 skill 盘点，对象不同。
- 需要**复核上限值**或**查平台有没有新槽** → 走**机制级取证**（直接读客户端的源码 / 资源包；本 skill 只消费结论，不做源码取证）。

---

## 1. 三条第一原则

1. **"注入"不等于"常驻"**。绝大多数槽在**首轮注入一次**（受"已注入"门控），此后不再重复。⇒ **换槽只解决容量 / 语义 / 跨机同步三件事，永远不解决「模型会不会照做」。** 想治行为漂移 → 走脚本 / 门禁，不要指望换槽或加重语气。
2. **体量一律用字符数**（`wc -m` 等价口径）。**行数完全无效**（同样 89 行，中英混排能差 3 倍）；**字节数会高估 3 倍**（中文 3 字节/字）。历史文档里凡是"XX 行以内"的口径一律作废。
3. **只治「用户资产」**。平台自动生成的槽（目录树、二进制环境信息）不是你的内容，**别治它的体量** —— 只能改结构（把文件收进子目录）或接受现状。

## 2. 注入层全貌

| 槽（对应注入块） | 源 | 上限 | 超限行为 |
|---|---|---|---|
| 工作记忆 | `<项目>/.workbuddy/memory/MEMORY.md` | **8000 字符** | 截断 **+ 追加"立即清理"强指令** |
| 用户记忆 | `~/.workbuddy/MEMORY.md` | **4000 字符** | 截断 |
| 云档案 | 云端归档（本地有缓存副本） | **10000 字符** | 截断 |
| 项目说明 | `CODEBUDDY.md` / `AGENTS.md`（**首个命中即停**） | **8000 字符** | 省略 |
| 项目规则（军规） | `~/.workbuddy/rules/` ＋ `<项目>/.codebuddy/rules/` | **40000 / 每文件** | **整条丢弃**（不截断） |
| 个人指令 | 配置项 `personalization.customPrompt` | **1500 字符** | **静默丢弃**（无报错） |
| 身份三件套 | `~/.workbuddy/SOUL.md` / `IDENTITY.md` / `USER.md` | **10000 / 每件** | 截断 |
| 目录清单 | 自动扫项目根目录 | **40 条** / 6 层 / 5 后缀 | 第 41 条起**完全不可见** |
| HANDOFF 等交接件 | — | — | **不注入 → 无槽位**，只算 Read 成本 |

**超限行为四档，严重度递增**：

```
截断  <  截断＋追加强指令  <  静默丢弃  <  整条丢弃
（丢尾）  （还派活给你）      （无报错）    （白写）
```

> ⚠️ **最危险的是"静默丢弃"**：输入框会直接吞掉超出的字符、**不给任何报错**。判据靠**字符计数**，不靠有没有红字。

**截断标记 → 归因对照**（看见标记就知道是哪一层、跟哪个上限比）：

| 标记 | 含义 |
|---|---|
| `... (memory truncated — MEMORY.md is too large)` + `ACTION REQUIRED` | 项目级工作记忆超 8000 |
| `... (user memory truncated)` | 本地用户记忆超 4000 |
| `... (user memory truncated — exceeded character limit)` | 云档案超 10000 |
| `... (binary context truncated …)` | 二进制环境信息超 10000 |
| `[...too long, omitted...]` | 项目说明超 8000 |

► 详表与开关清单见 `references/limits-and-signals.md`。

## 3. 流程：体检 → 判定 → 治理 → 验收（＋日常运维 S5）

### S1 · 体检（只读，零写入）

```
python3 scripts/scan_injection_surface.py
```

一次扫出：**全部容器** ×（工作记忆 / 用户记忆 / 规则 / 身份 / 目录条数）→ 每项给"越线 / 贴线 / 偏高 / 安全"。

**容器全集怎么来（这一步最容易出错）**：必须从平台会话数据库取 —— `workspaces` 表 ∪ `sessions` 表的 distinct 工作目录。
⛔ **不得用 `ls ~/WorkBuddy/*/` 之类的目录列举去猜**：那样会把**不在注入路径上**的目录（例如某个项目的仓库根目录）也算进来 → **假阳性**，把一个没事的对象报成"正在截断"，且这个错会扩散到后续所有文档里。

> 判据补一句：**"在文件系统里存在"≠"在注入路径上"**。报"某对象会被注入"之前，先证明它落在上面的源路径上。

### S2 · 判定（两维，别按文件大小排序）

| 维度 | 取值 |
|---|---|
| **A 急迫性** | 🔴 **越线** >100% ｜ 🟠 **贴线** ≥95% ｜ 🟡 **偏高** ≥80% ｜ 🟢 **安全** <80%（都按**该槽自己的上限**算；脚本 `level()` 同源实现） |
| **B 可治性** | ✅ 用户可直接编辑 → 能治 ｜ 🟡 间接（改目录结构等）｜ ❌ 平台生成 → 只能换入口或接受 |

**动手条件**：🔴 当场止血（不等下个会话）｜🟠 本波启动退场｜🟡 登记观察 + 写前必量。**且 B = ✅。**
其余只在报告里记一行，不排期。

### S3 · 治理 —— 按槽分派五种手段

| 手段 | 适用槽 | 要领 |
|---|---|---|
| **A 拆 + 外移** | 项目级 / 用户级记忆、身份三件套 | **两级退场**：**一级**＝整节外移到同级 `<对象>_外移_<年月>.md`，原位留 1 行可跳转指针；**二级**＝节内密度约束，触发线见下。主文件留"黄金区 + 指针行"，**目标留 20% 余量**（上限 8000 → 主文件 ≤6400） |
| **B 节流 + 写前预算** | 同上 | **每次写入前先量余量**；装不下就改写进外移件，**不要硬塞** |
| **C 结构瘦身** | 目录清单槽 | 条目 >40 时把过程件（备份 / 试点 / 快照 / 对比页）收进子目录腾名额。**这是"可见性"问题，不是磁盘问题** |
| **D 换入口 / 用开关** | 云档案等平台侧对象 | 优先用平台提供的开关；没有就走"接受 + 说明"，**不要用改权限之类硬堵手段**（会破坏锁与轮询） |
| **E 仅立规则** | 空槽 / 非用户资产 | 不动手，只立一条自律线（如"某文件一旦启用即 ≤6400"） |

**外移三原则**：① 外移件与主文件**同级**、命名带年月；② 主文件留**指针行**（"完整内容见 XXX"），否则下次没人找得到；③ **只搬不删**，内容零改动。

**两级退场（先一级，不够再二级）**：

| 级 | 触发线 | 动作 |
|---|---|---|
| **一级** 整节外移 | 该槽 ≥ 上限 95%（🟠 贴线） | 整节搬到同级 `*_外移_<年月>.md`，原位留 1 行可跳转指针 |
| **二级** 节内密度约束 | 一级之后**仍 ≥95%**；**或单节 > 该槽上限的 20%**（8000 → 1600） | 节内**过程数据**下沉到外移件；主文件保留「1 行指针 + **全部跨任务可复用条目**」 |

**二级的判据只有一条**（**不是**"重不重要"）：**这条内容下一次别的任务还用不用得上？**
- 用得上（跨任务可复用的纪律 / 口径 / 陷阱 / 判例）→ **上浮**，留主文件。
- 只用一次（项目过程数据：档案清单、本项目数字、一次性内参、结论推导过程）→ **下沉**。

⚠️ 二级**不是**"删节只留指针"：下沉的内容必须**完整落进外移件**（不减字、不摘要），主文件留的指针必须是**真路径**。
> 经验值：一级对**水分型**文件有效；对**密度型饱和**文件收效很小（实测 −6.6%）—— 那时别硬砍，转二级。

### S4 · 验收（必须带负控制）

1. **重测**：治理后再跑一次 S1，**数字必须变**。
2. **负控制**（关键，防"假绿"）：在临时目录造一个**假的越线对象**（灌到 >上限）→ 脚本**必须报红**；同时真实环境必须全绿。
   > 只能绿、不能红 ⇒ 说明你的检查根本没生效，是假绿。
3. **动态验证单列**（**已可脚本化，不必干等下个会话**）：跑 `--session` 模式，读**会话开场注入块**（原文落盘在 `projects/<slug>/<uuid>.jsonl` 开头几条记录里），逐槽与磁盘真源对照。
   ⚠️ 注入块＝**开局快照**，同一会话内不刷新 ⇒ **只能用「改动之后启动」的会话去验**；手头没有这样的会话，就如实写「待新会话验证」，别写成已验证。
   ⚠️ 边界：身份 / 规则 / 项目说明 / 目录 / customPrompt **可证**；**工作记忆与云 profile 不走这个块**（走系统提示、不落盘）⇒ 这两者的注入性此法证不了。

### S5 · 日常运维（跑完一次疗程之后，怎么持续）

| 时机 | 动作 |
|---|---|
| **写入前** | 先量现值（字符数）：🔴 / 🟠 先退场再写入；🟡 可以写，但写完须复核未越线（**退场目标**＝落回上限 **80%** 以内） |
| **收尾时** | 读当次体检结论；**见 🔴 当场止血**，不留到下个会话 |
| **每周一次** | 全量体检（容器全集来自会话数据库）；报告落**独立文件**，⛔ **不写回任何记忆文件** |
| **结构变更后** | 槽位清单是否增减 / 新版本是否改上限 → 按 `references/limits-and-signals.md` §7 复核 |
| **改过任一注入件之后** | 跑 **§10** 的 `check_parity.py`：同一容器的多份注入件不许对同一件事各说各话、不许同一段抄两份 |

**一条红线**：**退场动作由人授权后执行**；脚本只读、只写报告，⛔ 绝不写注入对象正文。

## 4. 槽位归位：这句话该放哪个文件

**按语义归属，不按容量剩余。** 四槽分工：

| 槽 | 语义（平台对模型的措辞） | 该装什么 |
|---|---|---|
| 个人指令 `customPrompt` | "少量规则，适用于**所有**会话" | **个人说话规矩**（语言/格式/口吻），小事 |
| 项目规则 `rules/` | "**当作用户亲口说的**来遵循" | **行为纪律（军规）** —— 语义最贴 |
| 项目说明 `guidance` | "由 IDE 的 AI 生成的**项目说明**" | **这个项目是什么 / 怎么跑** |
| 身份三件套 | "体现其人设与语气" | **人是谁**（人格 / 身份 / 用户档案） |

**判断顺序**：
1. 这条是"**人是谁**"吗 → 身份三件套。
2. 是"**这个项目是什么**"吗 → 项目说明。
3. 是"**跨项目都要遵守的行为纪律**"吗 → 项目规则（用户级或项目级）。
4. 是"**我的说话习惯/格式偏好**"吗 → 个人指令。
5. 都不是 → **它不是注入层的事**，放文档里，别塞槽。

⚠️ **规则的两条硬约束**：只认 `.md` / `.mdc`；单文件超 40000 会**整条丢弃**。另：带 `paths` 的**条件规则当前不生效**（只有"总是应用"的会真注入）—— 别把关键纪律写成条件规则。
⚠️ **规则注入顺序**：用户级先、项目级后（后者语义更强）。

## 5. 首装：新机器 / 新容器（三件套 → 军规 → 治理自律规则）

> 与 §3 的分工：**§3 是已经装好了、来治病；本节是第一次装。**
> 详版（每条的目标体量、逐项验收清单）见 `references/first-run-setup.md`；填空模板见 `assets/first-run/`。

**先判走哪条路** —— 问一句：**这段话换到这台机器上还成立吗？**

| 情形 | 走哪条 |
|---|---|
| 源机已有全套，内容原样可带走 | **迁移**（搬文件，不重写）→ §6 |
| 什么都没有，从零开始 | **首装**（写内容）→ 本节 1→3 |
| 源机有，但本机语境不同 | **三件套按本节重写 + 其余迁移** |

**三步**：

| 步 | 装什么 | 落点 | 最容易做错的一条 |
|---|---|---|---|
| 1 | **身份三件套**（人是谁） | `SOUL.md` / `IDENTITY.md` / `USER.md`（配置目录根） | ⛔ **别把别台机器的整份拷过来** —— 机器名、账号、常驻项目都不同，整份复制＝这台机器自称别人 |
| 2 | **军规**（纪律是什么） | `~/.workbuddy/rules/`（跨项目）或 `<项目>/.codebuddy/rules/` | 只认 `.md`/`.mdc`；**带 `paths` 的条件规则不注入** |
| 3 | **治理自律规则**（怎么维护自己） | 同上；现成文件见 `assets/first-run/rules/09-injection-layer-discipline.md`（ASCII 名防跨平台乱码，落位可改名） | 落位前**按本机核对上限值**（上限随版本变） |

**顺序硬约束**：**先写文件，再让客户端跑第一次会话。** 平台的初始化写入是「只补缺、不覆盖」式的。

**免费信号**：三件套内容 ≠ 默认模板 ⇒ 平台**直接记为「已完成引导」**，不再来问一轮"你是谁"。

**验收**（静态随时可证；动态用 `--session`，但**必须用改动之后启动的会话**）：

| # | 信号 | 怎么验 |
|---|---|---|
| 1 | 体量合规 | 跑 §9 的体检脚本，新增对象全部 ≤ 上限 |
| 2 | 真是自己写的 | 拿默认模板的特征串当探针 → **0 命中** |
| 3 | 落位正确 | 逐文件核对源路径（见 §2 表） |
| 4 | **动态** | `scan_injection_surface.py --session --cwd <容器>` → 逐槽看块内是否命中磁盘当前内容 |
| 5 | 负控制 | 造假越线对象 → 脚本**必须报红** |

## 6. 跨机迁移：三通道判定

**先判"这个东西属于哪一类"，再决定搬不搬、怎么搬**：

| 通道 | 判据 | 处置 |
|---|---|---|
| ① 云侧 | 同账号即回 | **不搬**（重复搬反而冲突） |
| ② 随项目 | 挂在项目目录里 / 进 git | **随目录走**，不额外操作 |
| ③ **机器本地** | 只在 `~` 下、不随项目、不上云 | **必须手工搬**：身份三件套 · 用户级记忆 · 外移件 · 规则目录 · 配置中的个性化段 · skills · 连接器授权 |

**两条硬纪律**：

1. **顺序不可反**：身份三件套 **先拷文件、后启动客户端**。平台的初始化写入是"**只补缺、永不覆盖**"式的 —— 顺序反了就得手工合并。
   > 附带收益：只要内容 ≠ 默认模板，平台就**直接记为"已完成引导"**，不再来问一轮"你是谁"。**这也是天然的验收信号。**
2. **别信工具文档，去读它的收集范围**：打包/迁移工具的文档写的是**意图**，收集函数写的才是**事实**。凡"会不会丢东西"的问题，**只认函数** —— 常见缺口是它不收根目录下的本地记忆与外移件。搬完必须**逐项核对目标端是否真落地**。

## 7. 红线（违反会白干或丢数据）

1. **平台配置项一律走 UI，不写配置文件。** 直接改盘上的配置文件**既不生效**（运行时读的是进程内副本）、**又会被覆盖**（下一次保存会用副本全文重写整份文件）。凡"改配置"，让用户去界面点。
2. **动任何文件前先备份**（复制到归档目录或 `_外移_<年月>`），**绝不删**；宁可多一份留底。
3. **同源文档不留双份**：要么软链，要么指针行。双份必然漂移。⇒ **已挂机检**：见 **§10**（`check_parity.py`）。
   > ⚠️ 本条曾长期"只写不挂"：话写在这里、没有任何动作会去查它 ⇒ 直到人自己发现两份注入件说出**互相矛盾**的版本才暴露。**规则没有触发点就不生效** —— 每条红线要么挂动作、要么配脚本。
4. **大更新新建文件、旧版标弃用**，不覆盖旧版。
5. **同一文件不并行编辑**（两次写入互相覆盖、且两边都报成功）。
6. **交付文档里的一切体量数字，交付前重测**（反复追加会漂移，旧计数不可信）。
7. **纠错要留痕**：发现已发出的结论有错，在**原文处**标"曾错报 + 纠正依据"，别静默改数；且**全库扫一遍**（同一处错报往往被复制到多份文档）。

## 8. 陷阱清单

| 陷阱 | 症状 | 对策 |
|---|---|---|
| 用行数 / 字节量体 | 治理排期全错 | 只用字符数 |
| 用目录列举猜容器全集 | 报出**假阳性** | 容器集只从会话数据库取；"存在"≠"在注入路径上" |
| 把"我没搜到"当"不存在" | **假否定** | 断言不存在前，先做**声明形式穷举**（两种声明形态都要覆盖：前缀式 ＋ 字段式） |
| 把文档描述当实际行为 | 静默丢数据 | 只认代码 / 收集函数 |
| 单源搜索 | 假否定 | 收口判据＝**多源穷举 + 观测集全覆盖**（把看到的东西逐个回查来源，全部可追溯才算完） |
| 以为超限都会报错 | 白写 | **静默丢弃**那两类不给任何提示，只能靠计数防 |
| 把"再探一轮"当安全感 | 无限游戏 | 问的不是"还有没有新发现"，而是"**新发现会不会改变方案骨架**"；不改骨架就冻结、转执行 |
| 用换槽治行为漂移 | 反复无效 | 漂移只能机制化（脚本 / 门禁） |
| 把别台机器的三件套整份拷来 | 机器自称别人、按别人的判据干活 | 三件套按本机重写；只搬真正跨机不变的部分（如称呼） |
| 一级退场做不动就硬砍 | 砍掉跨任务可复用的条目 | 转**二级**：先问"下次还用不用得上"，再定上下浮 |
| **红线只写不挂** | 洞照出、没人响，直到人自己撞见 | 每条红线配**触发点**（挂在某个动作上）或**机检脚本**；只写一句话＝没生效。§7.3 是此病实例，解法见 §10 |

## 9. 脚本

`scripts/scan_injection_surface.py` —— **纯标准库、只读、跨平台（macOS / Windows）**。

```bash
# 全量体检
python3 scripts/scan_injection_surface.py

# 只看某一层（工作记忆 / 用户记忆 / 规则 / 身份 / 目录 / 项目说明）
python3 scripts/scan_injection_surface.py --only rules

# 指定容器根目录（默认自动探测）
python3 scripts/scan_injection_surface.py --root ~/WorkBuddy

# 动态验证：读该容器【起点最新】会话的【开场注入块】，逐槽与磁盘真源对照
# （只读；不需要数据库；要"改动之后启动"的会话才作数）
python3 scripts/scan_injection_surface.py --session --cwd ~/WorkBuddy/某容器

# 要点名某一场特定会话（默认取起点最新的那场）：
python3 scripts/scan_injection_surface.py --session --session-file ~/.workbuddy/projects/<slug>/<uuid>.jsonl
```

**它做什么**：自动定位平台数据库与配置目录 → 取容器全集 → 逐个量各槽字符数 → 按上限分级输出；
`--session` 另走一路：定位 `projects/<slug>/` 下**开场起点最新**的会话记录 → 取开头注入块 → 报「哪些槽在场 / 块内内容是否＝磁盘当前内容 / 哪些件没进块」。
它还会打印**会话起点**与**末次写入**两个时间，并列同容器其它会话 —— 你可以据此判断手里这场能不能验到你的改动。

**选了「起点最新」而不是「mtime 最新」的原因**（踩过的坑）：**你就在某个会话里跑本脚本时，那个会话自己一直在被追加写入，永远赢 mtime 竞争** ⇒ 按 mtime 会拿到「你正坐着的这个会话」，而不是你想验的「新开会话」。起点时间不会因为后续写入而改变。
要指定某一场特定会话（例如窗口里第三新的那场），用 `--session-file <jsonl 路径>` 直接点名。

**怎么读 `--session` 的结果**：块内**未出现**某槽 ≠ 没配 —— 先排除「该会话起点早于你的改动」（注入块是开局快照）。
工作记忆 / 云 profile **不走这个块**，所以它们的"是否被注入"此法证不了，只能靠静态体量 + 行为观察。

**它不做什么**：不写任何文件（连临时库都是只读副本）；不改动目标；不替你删东西。

**首次运行要核对的**：脚本自己打印出它探测到的**数据库路径**与**配置目录**，逐项确认无误再用。找不到就手工指路 —— **不要**让它默默空转。

## 10 · 注入件一致性（同一容器多份注入件不许打架）

> 由来：2026-09-24 实测发现同一容器的 `MEMORY.md` 与 `CODEBUDDY.md` 有 **16 项内容重叠**，其中「转写·视频腿」一项**直接互相矛盾**（一份说走本地、一份说走云端）⇒ 按错的那份执行会 OOM。
> 而治理它的红线（§7.3）**早就写在本文档里**，只是没有触发点，所以一直没响。**本节是那条红线的落地形态。**

### 三种坏法

| 坏法 | 症状 | 后果 |
|---|---|---|
| **冲突** | 两份对同一事实说出相反版本 | 读到哪个按哪个 ⇒ 一个必错，且错的那次往往表现为"莫名失败" |
| **重复** | 同一段内容两边各抄一份 | 改一边、另一边不动 ⇒ 必然漂移（红线 3） |
| **双删** | 治理时两边都以为对方有 ⇒ 都删 | 事实消失，且没人发现 |

### 先分家，再查一致（归位判据）

| 该装什么 | 放哪 |
|---|---|
| **裁决态**：为什么这么定 / 踩过什么坑 / 不许再问 | 工作记忆 `MEMORY.md` |
| **指路**：路径 / 端口 / 凭证落点 / 命令 / 段位归属表 | 项目说明 `CODEBUDDY.md` |
| 行为纪律 | `rules/`（用户级 / 项目级） |

⇒ **工作记忆答「为什么」，项目说明答「在哪」。同一句两边都答了，就是重复。**
容量不够时优先砍**指路类**（迁去项目说明，它没有 8000 限制那么吃紧、语义也更贴），**不要砍裁决态**。

### 机检

```bash
python3 scripts/check_parity.py --facts <facts.json> --root <容器根>        # 正测：红 → exit 1
python3 scripts/check_parity.py --facts <facts.json> --root <容器根> --neg  # 负控制：必须见红
```

三类判据（只用**存在性判定**，不引相似度阈值）：

| 判据 | 含义 |
|---|---|
| **P1 不冲突** | `forbid` 串（过时/错误表述）在**任何**注入件里零命中 —— 防旧版本复活 |
| **P2 不丢** | `must` 串在**至少一个**注入件里命中 —— 防两边一起删干净 |
| **P3 不重** | `dup` 串（某块内容的特征串）命中**文件数 ≤ 1** —— 防同一段抄两份 |

`facts.json` 由**容器自带**（建议落 `<容器>/.codebuddy/injection_parity.json`，⛔ **别落记忆区**，它不进注入却会被当成记忆项）。格式见脚本头注释。

**验收**：正测全绿 ＋ 负控制**必须见红**。`--neg` 自带探针；更强的证据是**把旧的错误表述真塞回去**，看它报不报（只读内存注入，不动磁盘）。

**新洞现形时**：`facts.json` 加一条、跑一次 ⇒ **洞只现形一次**。

**为什么加（洞的由来）**：不是体检发现的，是**用户从产出异常倒推**发现的 —— 他问"MEMORY 里到底还存着些什么？规则不是都应该有专用槽吗？"⇒ 顺着查才发现两份注入件 16 项重叠、1 项直接打架。
**教训**：体量治理（§3）只回答"装得下吗"，**不回答"装得对吗 / 两边一致吗"**。这两件事必须分开治 —— 本次瘦身把记忆区压掉 61%，但两份注入件的重叠**一条都没减少**，因为根本没查。

**对外发布版必须剥离**：① 本容器 `facts.json` 里的具体事实（视频腿引擎、端口、凭证文件名）＝本机业务细节，示例一律改通用占位；② §10 由来段里的容器名与"OOM"等本机语境 → 抽象为"某事实两边说法相反，按错的那份执行即失败"；③ 本机绝对路径 → 占位符。**脚本本身可原样发布**（通用、无硬编码）。

**对外版可补**：给一份通用 `injection_parity.json` 模板（3 条起步：一个 forbid / 一个 must / 一个 dup），让新容器照抄即可用。

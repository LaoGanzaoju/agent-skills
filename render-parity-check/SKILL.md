# render-parity-check —— 「看起来一样」不算同源

## 何时用

- 一个编辑器 / 生成器有**多个渲染路径**：编辑面、预览、导出（PNG/PDF/HTML）、后端重建。
- 用户报「预览和导出对不上」「导出跟我看到的不是一个东西」「换个环境就变了」。
- 你要动**样式装配 / 序列化 / 排序 / 尺寸**附近的代码。

**核心判据：不要用眼睛验收「一致」，要拿计算值验收。** 视觉一致经常是「两台机器上恰好都命中了同一个后备字体 / 同一个默认值」——那是**巧合同源**，不是同源。

## 配方：同内容 × N 宿主 → 比计算值

1. **固定一份内容**（同一段 HTML 片段，含：有 class 的块 + **无 class 的裸块** + 图片占位）。
2. **为每个宿主各造一个最小场景**（不要跑整套应用；直接复刻宿主的**装配逻辑**）：
   - 编辑面：Shadow DOM —— 宿主元素 + `attachShadow` + 把模板 CSS `:root` 换成 `:host` 塞进去
   - 预览：真 `document` + `<body style="margin:0;padding:0;background:#fff">` + 同一份 CSS（`:root` 保留）
   - 导出：真 `document` + 复刻后端拼 HTML 的方式（每页自带 `<style>` + body 内联零边距）
3. **量同一组计算值**：`font-family`（**整个字符串**，别看渲染效果）、`font-size`、`color`、容器 `background-color` / `padding` / `overflow`、纹理层 `z-index`/`position`。
4. 三者逐项比对，**打印原始值**，不打印「一致/不一致」的空结论——甘/用户要能看到差在哪。

一次 Chrome headless `--dump-dom` 就能取回结果：把结果写进 `document.title = "RESULT" + JSON.stringify(r)`，正则抓 `<title>`（Shadow DOM 内部节点不出现在 dump 里，但**结果字符串**能出来）。

## 高频根因清单（都真撞过）

| # | 根因 | 症状 | 修法 |
|---|---|---|---|
| 1 | **`body`/`html` 选择器在 Shadow DOM 里不匹配任何元素** | 模板是靠 `body{font-family:var(--sans-zh)}` 给字体基线的 → 编辑面里**无 class 的块**只拿到外层主文档的字体栈；有 class 的块因自带 `font-family` 而看不出问题 | 在编辑面样式末尾**显式补宿主链规则**（`:host, .wrap, .poster{font-family:var(--sans-zh);color:var(--ink)}`）；**只搬「继承型」声明**（字体/颜色），**别搬** `body` 的 `padding` / `background`（那是给整页留白的，落到宿主会撑坏布局） |
| 2 | 只把 `:root` 换成 `:host` | CSS 令牌（`--paper` 等）对了，于是**以为**同源已达成 | `:root→:host` 只解决**变量**；`body`/`html` 是另一码事，见第 1 条 |
| 3 | **编辑期状态类随序列化持久化** | 选中描边类（如 `blk-sel`）被挂到 DOM → 随后任意一次 `syncPad()`/`innerHTML` 快照把它写进数据 → 进预览和导出的 HTML | 建**单一序列化入口** `serializePageHtml()`：克隆节点 → 剔除纯编辑期类 → 取 `innerHTML`；**所有**写回数据的路径都走它，载入时再防御性剔一次 |
| 4 | 固定画幅的**裁切口径**不一致 | 导出用 `--window-size=W,H` 截视口，编辑面用容器 `overflow:hidden` | 两边口径写成一条：容器固定 `W×H` + `overflow:hidden` ↔ 截图 `--window-size=W,H`；超高内容在两边都应被裁 |
| 5 | **文件名数字排序** | 导出多页 ZIP，页序乱 | `sorted()` 是**字典序**：`x-1, x-10, x-11, x-2 …`。文件名没有前导零时必须**按数字后缀排序**（`key=lambda f: int(re.search(r'-(\d+)\.', f).group(1))`）。≥10 个文件就会踩 |
| 6 | 前后端两张**映射表**各自维护 | 某版式在预览加了包裹类、导出没加 | 前端 `typeClass()` ↔ 后端 `TYPE_CLASS`，把 17 个版式**逐一对齐**并写进 PRD；改一处必须核另一处 |

## 该剔什么 / 该留什么（别一刀切清 data-*）

- **剔**：纯编辑期视觉状态 —— 选中描边、hover、拖拽中的临时类。
- **留**：**功能性**属性 —— 保护标记（`data-key`）、语义槽位（`data-sig`）、骨架原值（`data-role0`）、输入提示（`data-ph`）。这些是**数据**，换页/导出/换风格都靠它们；剔掉功能就没了。
- 判据：**换页往返后它还有用吗？** 有用 = 留；只是「此刻在选它」= 剔。

## 脚本形态：前置诊断（红）→ 修完（绿）

把它写成**阶段前置诊断**，而不是事后验收：

- 做之前跑 → 报 `RESULT: RED（N 项，红 M）`，退出码 1；
- 修完再跑 → 应转 `RESULT: GREEN`。
- **这条「红 → 绿」本身就是验收证据，且天然带负控制**（不动的代码库上它必须是红的，证明它测的是真东西、不是恒绿）。
- 每条断言都要带**明细数值**（`A="PingFang SC" | B="PingFang SC", SourceHanSansCN, …`），否则红了也看不出差在哪。

## 变体：两侧都只有位图（PNG）时怎么比 —— 用「行带」代理

回归基准常常只剩**一张已验收的图**（或只留了图），读不到 computed style。此时别退化成"肉眼看"，把**版面几何**从像素里量出来：

1. 二值化：`img.convert("L").point(lambda v: 255 if v < thresh else 0)`；
2. **按行**降采样成 1×H：`binimg.resize((1, H), Image.BOX)`（C 实现、快）→ 每个值 = 该行墨量占比；
3. 取超过阈值的**连续行段** = **行带** `[(y0,y1), …]`；
4. 比四项：**行带数量**（版面结构未变）、**带起点**（垂直位置）、**带高**（≈ **字号**代理）、**带间距**（≈ **行距**代理）。

配一组便宜的粗筛，互相印证：**逐像素差**（`ImageChops.difference` → `histogram()` 数非零像素 / `getbbox()` 定位差异区）、**角落与顶中像素**（背景色）、**文件字节数**（逐像素全等时字节数必相同——免费的独立佐证，本项目实测正例三张字节数一模一样）。

**阈值必须用「已知不同的两份真实产物」标定，别拍脑袋。** 本项目先把「新版基准 vs 旧版备份」这一对**真图**比一遍，得到"已知不同 = 6.3%–10.0% 差异像素"，再定"正例必须 0%"、"负控制必须 > 0.0005%"——判据才站得住。

## 变体：换机器之前，先量「字体到底存不存在」——宽度对比法

字体不一致是本类问题里**唯一在本机看不见**的一类（本机两条路径恰好都命中同一后备字体，于是"看起来同源"）。换机前先把环境钉死，别等到了那台机器才发现。

1. **探针用 DOM，不要用 canvas**。`canvas.getContext('2d').measureText` **不认 CSS 字体关键字**——`-apple-system` / `system-ui` / `sans-serif` 用 canvas 量出的宽度差**恒为 0**，会被误判成"该字体不存在"。改用 `div` + `getBoundingClientRect().width`，在真实 CSS 上下文里量。
2. **同一串 + 同一 fallback 基准**：`font-family: "<候选>", monospace` 与纯 `monospace` 各量一次。宽度不同 ⇒ 候选**真存在**；相同 ⇒ 不存在（退化了）。
3. ★ **"量到了宽度" ≠ "字体存在"**。候选不存在时会**静态退化**到链里的下一个 / fallback，所以它**永远有宽度**。必须再单独量一个**已知单品**（如 `PingFang SC`）对宽，才能回答"这整条链**实际命中的是谁**"。
4. **量一条链 = 知道"改栈有没有副作用"**。若 `整链宽 == 某单品宽`，那么把栈首改写成该单品，**本机渲染零变化** → 已验收的基准图**不用重验**。（本项目：`"Noto Sans SC", -apple-system, "PingFang SC", …` 实测 == `PingFang SC`(244.05)，故钉死栈首无副作用。）
5. **两套名字要分清**：栈里写的名 ≠ 字体**内部 family name**。用 `mdls -name kMDItemFonts <字体文件>` 查真名——本项目 `/Library/Fonts/NotoSansHans-*.otf` 的真名是 `Noto Sans S Chinese`，而栈里写的是 `Noto Sans SC` → **装了也匹配不上**（**但必须实测确认，见第 11 条：`"LetterGothicStd"` 这种反例确实存在**）。
6. **`.ttc` / `.otf` 能否被 `@font-face` 直引，先测再设计**。`.ttc` 是集合包（苹果苹方那**一个文件里 36 个字体、77MB**），直觉上"浏览器大概不吃"。**实测能直接吃**（`document.fonts.load` 返回 1、宽度真变）——别凭直觉跳过验证，也别凭直觉认为必须先转格式。
7. **体积是隐藏成本**：苹方 77MB / Songti 66MB。真要"从一个机器 serve 字体给另一个机器"，先想清楚拆包（只留用到的字重），否则每次开页面都在传几十 MB。
8. 负控制：`@font-face` 指向**不存在的路径**必须报失败（本项目报 `NetworkError`），否则你的"能加载"是假绿。
9. ★★ **终审证据不是宽度，是内核自报的「平台字体」**。宽度法在**中文字体之间几乎没有分辨力**（汉字全宽：`信息差是便宜的杠杆` 在 100px 下**任何**中文字体都量出 900px），且"不存在→静态退化"会让所有候选都显得"存在"——本项目第一轮就因此把结论下偏。一句话定案用 CDP `CSS.getPlatformFontsForNode`：`DOM.enable` + `CSS.enable` → `DOM.getDocument{pierce:true}` → `DOM.querySelector` 取 nodeId → 返回**真实选中的 familyName / postScriptName / glyphCount**。纯标准库即可实现（本项目 `web/_probe_font_actual.py`）。
10. ★ **必须把「汉字段」和「字母/数字段」分开问**。等宽槽（编号、标签、数字）只对拉丁字符生效，汉字会**另找兜底**——只问一个字符段会得出**相反**的结论（本项目第一版只看汉字段，误判"等宽槽命中苹方"；分字符段后真相是 `Letter Gothic Std`）。同理 **`document.fonts.check()` 对系统字体一律返回 `true`**（连 `___NoSuchFontXYZ___` 也 true）→ **不可用作字体可用性判据**。
11. ★ **「死名 vs 真名」体检是一条独立的免费加固**。浏览器**不做去空格归一化**：`"SourceHanSansCN"` 不匹配 `Source Han Sans CN`、`"Noto Sans SC"` 不匹配 `Noto Sans S Chinese`（写死名 → 退化到兜底；写真名 → 命中）。**但也有反例**：`"LetterGothicStd"` 实测**能**匹配 `Letter Gothic Std`（老版 Adobe 字体把无空格形式注册进了 name table）→ **只能实测，不能靠推理判死活**。查真名：`mdls -name kMDItemFonts <字体文件>`（输出会混着 family / full / PostScript 名，要挑对）。
12. ★ **改名字只准改字面、绝不动顺序**——**顺序决定谁生效**。判据：把"改名后的链"与"当前链"各问一次内核，family 相同 ⇒ **本机零影响、已验收基准不用重验**（本项目实测：改 4 个死名 → 三张范本 PNG **逐像素零差异、字节数相同、16 项 GREEN**）。**例外要警惕**：若某槽**第一位**是死名、后面还有可用字（典型 `"LetterGothicStd"`(死) → `"Monaco"`(可用)），那么"把名字改对"会**真的换字**（本项目该例名字本来就有效，故未触发）→ 这种槽**必须先确认再动**。
13. **两层样式清单要分清谁生效**：上游模板自带的字体栈（残留）+ 「本机化」覆写文件（本项目 `src/fonts-local.css`，**在模板之后注入 → 同名 `:root` 变量由它赢**）。上游那层的死名**被覆盖、不生效**——别对着它下"改了就换字"的结论。**先看拼接顺序确认哪层生效**（本项目 `server.py`：`poster_style = 模板CSS + _FONTS_CSS`、`/style = _STYLE_CSS + _FONTS_CSS`），再判影响。

## 坑

1. **本机测不出 ≠ 没问题**：字体栈不一致在「本机两台路径恰好都命中同一字体」时**完全看不见**，只有换机器（另一台没装那个字体）才暴露。→ 所以要比**字符串**，不要比渲染结果。
2. 临时取证脚本（只想查一个值）**不要改正式验证脚本**：写临时脚本 → 生成到被 serve 的目录（为了相对引用 `app.js`）→ **跑完立刻删** → `ls` 复查目录只剩正式文件。
3. `--virtual-time-budget` 给太小 → 页面被 dump 时脚本还没跑完 → 拿到的是半成品/空结果（我曾把 `stabilize()` 的 9 秒×2 圈超了 12 秒预算）。异步链路长的探针直接给 60000。
4. 同一份 CSS 的**加载方式**不同（`fetch` 后替换 / `<link>` / 服务端内联）本身不是问题——**内容同源**才算数；但要把「三处装配代码」抽成共用模块，否则必然漂移。
5. ★ **验收脚本里"再写一遍"生产逻辑 = 假绿流水线**。本项目已抓 3 例：诊断脚本自己 `sorted()` 一遍再跟数字序比（压根不读被测代码 → **永远红、修了也不会绿**）；脚本里**复刻** `injectStyle`；脚本里复刻版式映射表。判据：**这段逻辑改了，脚本会跟着变吗？** 不会 = 复刻。修法：**import 真源**——为此可以把生产脚本重构成可 import（执行段收进 `main()` + `if __name__ == "__main__"` 保护，payload 留模块级），这比让验收脚本"知道"实现细节干净得多。
6. **负向断言（"不得误报"）在功能整体缺失时会恒绿**——做负控制时要认出这一点：整轮负控制里混着几条"恰好通过"是正常的，但**不能靠它们**证明能红；要挑正向断言看红。同理，夹具要**从真源派生**（真骨架 + 真角色表），否则改骨架后夹具不会跟着变，测试仍在旧假设上跑。

## 坑（续）：跑探针 / 夹具时的无声失败 —— 比"写错逻辑"更常见（2026-09-28 补）

7. ★ **夹具入口可能「只摆状态、不渲染」**。应用常提供一个给测试用的 `loadFixture()` 类入口，注释写着"同步版、不触发渲染"——它只改内存数据，**不动真实 DOM**。你在它后面 `getComputedStyle()`，量到的是**上一页的残留值**。
   症状：**同一组不同夹具量出完全相同的值**（本项目连量三套风格都得到同一个 `gap:40px` —— 因为量的一直是同一份陈旧渲染）。
   ⇒ 量样式 / 截图前**必须走真渲染路径**（本项目是 `await loadCur()`），并 `await` 足够的 sleep 等异步样式注入（`await fetch(css)` 那类）落地。
   ⇒ 自检：**换夹具后，第一个量到的值必须跟着变**；不变 = 你没在量夹具。

8. ★ **带参启动会触发「自动回读」，把夹具整个覆盖**。编辑器常支持 `?dir=…&slug=…` / `--project` 之类参数，启动时**优先载入盘上已有稿子**。带参打开 → 夹具刚写完就被回读覆盖 → 量到的是盘上那份。
   ⇒ 只读探针 / 判据**一律不带这类参数**；非要带，先确认它不触发回读。

9. ★ **自动落盘会污染目录**。编辑器常有 `markDirty()` → 300ms 后自动写盘。你只是"摆了个夹具"，盘上就多出 `*.json` / `*.bak`。
   ⇒ 判据落盘落点一律放**专用 SANDBOX / 临时目录**；跑完 `ls` 复查目标目录没多东西。

10. ★★ **判据轴选错 ⇒ 结构性必然红（比假绿更隐蔽，会误导下一棒去"修"不存在的问题）**。判"某操作没破坏结构"时，若比的是**重建后的整串序列化结果**（`JSON.stringify(export())`、`innerHTML` 全等），任何"重建类"操作（换模板 / 重排 / 迁移）都**必然不等** —— 类名、注入的属性（如 `data-role0`）本来就要重写。**这个红不是缺陷，是判据选错了对象。**
   ⇒ 正确的轴是**内容集合守恒**：两侧各自解析成"叶子文字序列"，逐项比**是否都还在**（子串包含），而不是比字符串全等。
   ⇒ 自检：**这个断言在"正确实现"上能绿吗？** 不能绿 = 轴错了，别急着改代码。

11. ★ **产物级最硬判据是 sha256，但先证"真出了产物"**。同一渲染器、同一参数、唯一变量是你的那段 CSS ⇒ 产物 **sha 不同 = 真生效**，比 computed style 更靠外一层（本项目用它一锤定音：现行规则在两种风格上产物 sha **完全相同** = 零效应）。
   ⚠️ 但**两边都没产物时 sha 恒等**，会把"出图失败"误报成"控件是哑的"——同一个红，根因完全不同。**先断言产物数量 / 字节数 > 0，再比 sha。**

# SVG 长图出图

## 何时用 / 不用

- **用**：需要**文字精确**的图 —— 知识图解、结构图、流程图、对比表、信息长图、贴图号单页、公众号配图、FDE 交付图示、**脑图/思维导图（含 .xmind 转图）**。
- **不用**：需要**插画/氛围/写实质感**的图 → 走 `ImageGen`（AI 生图）或 miora/ardot 体系。AI 生图**不能承载文字**（官方文档明示「细密小字会被糊掉」）。
- **不用（改走别的 skill）**：**贴图号日常款**（科普讲透 / 一组词条 / 清单对照，四页长图）→ 走 `tietuhao-daily-template`（它是 editorial 模板 + `server.render_zip` 链路，版式已定版）；**技能发布类贴图号** → 走项目内 `贴图号编辑器/outputs_editorial_demo_v2_新范本_原生字距/`。本 skill 只在需要**手排 SVG**、或上述模板覆盖不到的形状（知识图解/结构图/流程图/脑图）时使用。

> 两者是**分层关系不是替代关系**：本 skill 出**骨架层**（结构+文字，精确可控），AI 生图出**素材层**（背景/插画/氛围）。合成方案尚未验证。

## 核心链路（★已实测）

```
SVG（含 viewBox + 具体 width/height）
  → 包最小 HTML（html,body{margin:0;padding:0;background:#fff}）
  → Chrome headless --screenshot
  → PNG
```

**关键：零新增依赖。** 本机 `cairosvg` / `PIL` / `rsvg-convert` / `inkscape` / `magick` / `playwright` **全都没装，一个都不需要**。只要 Chrome 与系统中文字体在位。

用 `scripts/render.py` 执行：

```bash
python3 ~/.workbuddy/skills/svg-long-image/scripts/render.py page.html \
  --width 1242 --height 1656 --out /path/out.png --scale 2
```

直接传 SVG 也行（脚本会自动包 HTML）：

```bash
python3 .../render.py page.svg --width 1242 --height 1656 --out out.png --scale 2
```

## 手作感技巧（实测有效）

1. **贴纸错位阴影**：同形状同色 rect 偏移 (+5, +7) 垫在主形状下、opacity 0.15–0.5 → 立刻有"贴上去"的手作感。比抖动线条更干净。
2. **手绘下划线**：用 `sin` 波形生成 polyline，`stroke-linecap="round"`：
   ```python
   pts = [(x1+(x2-x1)*i/seg, y+math.sin(i/seg*math.pi*2.6+seed)*amp) for i in range(seg+1)]
   ```
   `amp` 取 3–4px 足够。
3. **手绘连线**：贝塞尔故意不对称 —— `M615 490 C640 570 300 596 252 656`（控制点左右不对称，就有手画感）。
4. **虚线便签块**：`stroke-dasharray="9 7"` + 淡黄底 `#FAF0D8`。
5. **纸张底色**永远比纯白暖一档（`#FBF8F1`），且**留白要够**。

## 脑图 / 思维导图（`scripts/mindmap.py`）

**先破一个误解**：网上那些「手绘脑图」**既不是手绘、也不是 AI 画的** —— XMind 自 2022 起内置「手绘风格」骨架主题（一键切换）；Excalidraw 类白板是 `rough.js` **算法生成**（几何拆成采样点 → 加高斯随机偏移 → 贝塞尔平滑连接）。**GitHub 上没有现成的「手绘脑图生成器」**（实搜：`hand drawn mindmap` 仅 1 个非工具仓库、`sketchy mindmap` 0 命中、`mindmap python svg` 0 命中）。两半零件分别成熟——**`markmap` 管布局、`rough.js` 管拟手绘**——但**没人把它们拼起来**。本机就是把这两半拼起来。

```
缩进大纲 / markdown  或  .xmind 文件
      ↓  parse_outline()（rank 判据，兼容 # 标题与缩进混用） / xmind_to_outline()
  树结构 → 布局（4 种，auto 择优）→ 拟手绘渲染 → SVG → render.py → PNG
```

### 四种布局 + 自动择优

| `--layout` | 形态 | 适合 |
|---|---|---|
| **`auto`（默认）** | **试算 4 种的适配系数，取最大** | 不确定时的正确选择 |
| `htree` | 向右逻辑树（根在左） | **真实 xmind 的实测最优**（层级放横向、叶子放纵向，匹配竖版卡片） |
| `vtree` | 上下树（根在顶） | 层级少、叶子多的清单式内容 |
| `mtree` | 左右双侧脑图 | 经典脑图形态，**但在竖版卡片上通常最差**（宽度翻倍） |
| `radial` | 径向脑图（根在中心） | 展示「发散」感；节点用点+文字而非胶囊 |

**★ 实测（桌面 217 个真实 .xmind 抽样）**：`htree` 适配系数 **0.77–0.91**，`vtree` 仅 **0.23–0.59**（叶子全横向铺开，宽度爆炸），`mtree` 0.42–0.48。**故默认 `auto`，不要手写 vtree。**

### 两种输入

```bash
# A. 缩进大纲 / markdown（`#` 标题与 `-` 列表可混用）
python3 mindmap.py outline.md --out map.png --title "知识图解 · 001" --footer "副业雷达"

# B. 现成 .xmind 直接出图（Zen/2020+ content.json 与 XMind 8 content.xml 都认）
python3 mindmap.py "/path/xxx.xmind" --out map.png --max-depth 3 --style ink
```

### 关键参数

| 参数 | 说明 |
|---|---|
| `--max-depth N` | **大图必用**。截断到 N 层，被砍子孙数自动标注 `+N`（400+ 节点的 xmind 不截断会缩到 0.14 级、不可读） |
| `--style` | `handdrawn` 纸感手写（默认）/ `ink` 国风墨色 / `comic` 漫画粗描边 / `clean` 现代圆润 |
| `--max-text-width` | 节点文本折行阈值（默认 300；根与一级自动放宽 1.7× / 1.3×） |
| `--seed` | 手绘抖动随机种子（同种子 → 同结果，可复现） |

### 拟手绘的三个要点（「像手绘」的真正来源）

1. **采样点 + 高斯扰动 + Catmull-Rom 平滑** —— 与 rough.js 同法。风格预设里的 `roughness` 控制潦草程度，**1.1–1.8 是可用区间**，超过 2 会牺牲可读性。
2. **锥形笔触分支** —— 一级分支是**填充路径**（根部 17px 渐细到 7px），不是描边线；这是 XMind 手绘脑图的标志性形态。
3. **手写字体只做标题 / 一级分支，正文用 PingFang** —— 全篇手写体牺牲可读性。

### 脑图专有的出稿前检查

- [ ] 看 `[fit]` 诊断行的**适配系数 ≥ 0.7**（< 0.62 会打警告）—— 不够就 `--max-depth` 截断或换 `--layout`
- [ ] 节点文案尽量短（**文案越长 → 布局越宽 → 缩放越小 → 字越小**，硬约束）
- [ ] 大图先 `--max-depth 3` 出一版看结构，再决定要不要加层
- [ ] **稀疏内容（≤15 节点）在竖版卡片上天然留白偏多** —— 宽高比不匹配所致，非 bug；要么改小 `--height`（如 1242×1104 方版），要么接受留白走「留白即版式」路线

## 节点多的结构图：防重叠画法（★2026-09-27 甘三次纠偏后立）

> 起因：给甘画「流水线板块与接缝」图，连画四版都被判「重叠、遮盖、看不明白」。根子在**画法**，不在信息量。

- [ ] **一张图能说清的，一次画全，禁止迭代重画**。此前拆成多张的真实动机是「不确定画全了对方会不会一次判完」，省的是自己的犹豫，付的是对方每次重看的成本。
- [ ] **节点 >~10 个，放弃横向布局**（横铺方块＋连线＋支线绕行，连线横穿必然压字）。改**竖排单链**：板块自上而下，块与块之间嵌一条状态条。
- [ ] **接缝/关系不画连线** —— 关系本身即色块（条内写「A → B · 状态」）。跨节点连线是叠字遮盖的第一来源，能不画就不画。
- [ ] ⛔ **颜色必须写死内联值**（`fill` / `stroke`）。颜色类名（`c-green` 那套）在本环境**未生效**，用了整图渲染成黑白。
- [ ] 图例四档够用：绿＝形状对上且真跑过 · 琥珀＝形状对上没跑过 · 红＝形状对不上 · 灰虚线＝形状没定义。
- [ ] 讲口径时**不替历史拍板背稿**：台账只写「形状没定义」的，别宣称「当时已裁定不接」。

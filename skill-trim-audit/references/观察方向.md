## 方向一：微信桥接 Agent（WeChat bridge to AI agent）

- **记入日期**：2026-09-29
- **方向定义**：把微信消息自动桥接进 AI Agent（Claude Code / Codex / WorkBuddy / DSH 等）的插件/仓库，以及「在微信里直接跟 Agent 对话」的能力。
- **起因**：甘晓东问「这些 GitHub WeChat bridge 跟我现在手动从微信转发给你、打包一次，有差别吗」。研判结论＝**对手动转发场景差别不大，不值得专门搭桥**（省掉的只是一次复制粘贴，换来 iLink 接入 + 凭证 + 暴露微信会话的成本）。
- **首轮快照（2026-09-29 GitHub 检索 `WeChat bridge`，按星标）**：
  - `Johnixr/claude-code-wechat-channel` — **313★**，全场最高；经官方 ClawBot iLink API 把微信消息桥进 Claude Code。架构参考价值最大。
  - `pan17/wechat-bridge-opencode` — 17★；微信私聊 ↔ OpenCode。
  - `gtaifu/dsh-wechat-bridge` — 13★ / `lanbaolu/dsh-wechat-bridge` — 5★（DeepSeek Harness 系，最近两天还在更新）。
  - `roxorlt/cc2wx` — 10★；Claude Code ↔ 微信，走 MCP Channel 协议。
  - `leilong611-ai/weixin-codex-bridge` — 6★（Codex，local-first）。
  - `zhentong520/webchat-ai` — 2★；**唯一点名 WorkBuddy** 的（「WeChat AI integration with MCP - WorkBuddy WeChat bridge」），但星标极低、成熟度存疑。
  - 其余一堆 `dsh-*` / `opencode-*` / `codex-*` 桥，均为 2026 年 iLink 协议放开后冒出的轻量适配器，无标准答案仓库。
- **当前研判（2026-09-29）**：该方向很新很碎，没有成熟通用方案；最高星那个是 Claude Code 版，思路可平移但不直接给 WorkBuddy 用。对用户「转发内容给 CCS 处理」的用法，手动转发是最优解。
- **重新评估的触发信号（任一命中才回报，平时不报）**：
  1. **WorkBuddy 官方发布微信桥接**（最关键的信号）。

  4. 甘晓东需求变化：明确要「在微信里直接跟 Agent 对话」或「让 Agent 自动监控某号/群」。

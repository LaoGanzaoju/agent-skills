# skill-trim-audit — skill 使用度审计与交叉瘦身

> 触发：说「skill 瘦身」「盘点哪些 skill 没用」「交叉比对」→ 跑本 skill。
> 本质：把「感觉该删」变成「有调用证据的判定」，避免误删在用能力。

## 一、判据（唯一口径）

```
A = 副业规划需要的能力（保护名单，见 references/能力集A_默认.md）
B = 近 N 天真实调用的能力（会话留档工具调用级实扫）

在 A 或在 B  → 保留
两集合皆非   → 候选瘦身（仅为建议，动手前过三项检查）
```

**A 是主判据，B 是校验器。** 副业处于「信息积累期」，主链路大批 skill 会长时间不跑（甘晓东 2026-09-07 自记「过去一月实际未启动」）；若只看 B 会把整条链路删光。B 的真正用途是**捞 A 集之外其实在用的**。

## 二、统计口径（2026-09-12 实测确定，勿放宽）

| 口径 | 定义 |
|---|---|
| A 计数 | `function_call.name == "Skill"` 的**点名**调用（读 `input.skill` / `input.command`） |
| B 计数 | 命令参数或返回文本出现 `/skills/<名>`，**且该条只涉及这一个 skill**（过滤批量盘点噪声） |
| ✗ 弃用 | 裸 skill 名全文匹配 —— 读「瘦身清单」或系统注入的技能列表会让**全部** skill 命中（实测假阳性 100%） |

> 踩坑记录：首版口径直接数 skill 名，结论是 78 个 skill 全部「有使用」，完全失效。口径必须写死在脚本里，不要临场改。

## 三、执行

```bash
# 标准跑法（近 30 天）
<工作目录> \
  <工作目录>

# 给自动化消费（JSON 落盘）
... usage_audit.py --days 30 --json --out /tmp/trim_audit_30d.json

# 换能力集 / 只看使用集
... usage_audit.py --allowlist /path/能力集.md
... usage_audit.py --no-allowlist
```

耗时：全量 30 天约 2–4 分钟（扫 ~130 个会话 jsonl）。**必须后台跑**，前台会超时——单文件体量大，逐行流式处理，`output` 字段截断 20000 字符防内存爆。

输出四组：`core`（A∩B 核心）/ `used_only`（在用但不在名单→回补或判定可弃）/ `allow_only`（规划需要但近期没跑→保留，属缺口不属冗余）/ `candidate_trim`（候选瘦身）。

## 四、执行瘦身（铁律）

1. **`mv` 到备份区，绝不 `rm`**：
   ```
   <工作目录>
   ```
   还原：`mv <备份区>/<名> <工作目录>`
2. **裁量权边界**：以下三类**不得由脚本自动判**，必须回甘晓东确认——
   - 他亲自标过「必留/用户指定」的（如 `workbuddy-asset-migration`，2026-08-12 标注）
   - 另一空间在主用的（内训/内容线 expert 依赖）
   - **同族依赖**：删一个会连带废掉已验证路径的（如 `tencentcloud-ocr` 三件套里删两个）
3. **一次一批，报数核对**：移出前后都 `ls | wc -l`，数字对不上就停。
4. **报告落盘**：写 `副业能力集_使用集_交叉瘦身_<日期>.md` 到雷达工作区，含已执行清单 + 待确认组 + 保留大盘。

## 五、进料侧（为什么这是例行动作）

二类登记册持续进料（GitHub 仓库 / 视频号账号 / Agent 平台 / 新 skill），**进料不停 → 瘦身就不能是一次性**。

- **挂载点**：并入已有的周期性收敛任务（周一 09:00 收口锚点），加一步「跑本脚本 → 输出新增 zero-use 项」。
- **新增检测**：把本周的 `--out` JSON 与上周对比 `candidate_trim` 差集 = 本周新增零使用项。
- **回补动作**：`used_only` 里属副业链路的 → 补进 `references/能力集A_默认.md`。

## 五-B、出料侧 · 结果回写实验台清单（2026-09-24 立）

本 skill 不只在「进料侧」消费二类登记册，**也产出结论**——那些结论必须回写到调用方容器的实验台清单，否则「哪些要进实验台 / 进没进 / 结果怎么样」在流程上无处落地。

- **回写目标（调用方容器内）**：`素材库/二类登记_资源抽取/实验台清单.md`（二类产出主体件）＋ 根目录 `副业实验台_双轨表.md`（双轨真源）。
- **触发**：一轮瘦身 / 测评结束，或某候选被实际验证 / 安装 / 实测完成后。
- **回写字段**：`实验台状态` / `实测结果` / `升类结论`（两档：升为自沉淀主力 · 升为用途级一类）/ `结果落点`。
- **双向纪律**：清单点名进实验台 → 双轨表加行；双轨表跑完 → 结果回写清单。**任一侧单边改动＝断链。**

## 七、落地到 UI 的核验（2026-09-22 新增 · 禁用清单最终要靠人在 UI 点，此步不可省）

**根因**：报告给的是 **slug**（如 `wechat-similar-account`），但 WB 管理界面暴露的是**显示名**（如「公众号相似账号推荐」）。命名高度近似 ⇒ 点错风险真实存在（实测样例：「公众号相似账号推荐」vs「小红书相似账号推荐」；「公众号爆款封面设计」vs「小红书爆款封面生成」）。**禁用清单交付 ≠ 动作完成**，必须回核。

### 1. 显示名 / slug / 开关态 —— 权威来源（单一真相源）

平台 UI 自身的缓存文件：`<工作目录>`

| 字段 | 含义（**别用错**） |
|---|---|
| `slug` | 内部名（报告用） |
| `name` | **UI 显示名**（甘在界面上看到的） |
| `disableModelInvocation` | **=true 才是 UI 的「关闭」态** ← 真正的开关 |
| `disable` | ⚠️ **不是 UI 开关**，恒 false；首轮曾误读此字段导致「全绿」误判 |
| `source` | `userSettings` = 用户可管理项（管理界面里那批）；`builtin`/`connector`/`plugin` 另论 |
| `filePath` | 实体路径；`.../tencent-docx/skills/...` 等**插件内置子技能**常自带 `disable-model-invocation: true`（设计如此，非人关的，勿误报为"被关错"） |

```bash
# 一行导出：已关项 + 14 项清单逐条核验（把清单换成当次的）
<工作目录> -c "
import json
d=json.load(open('<工作目录>',encoding='utf-8'))
for e in d['results']:
    if e.get('source')=='userSettings' and e.get('disableModelInvocation'):
        print('OFF', e['slug'], e['name'])
"
```

**注意**：缓存 `savedAt` 为毫秒时间戳，先核它是否晚于甘的操作时刻；若早于，说明缓存未刷新，不可当现状。

### 2. 独立第二方法（反谎报 · 截图取证）

缓存是「工具 claim」；要独立确认，对 UI 截图做**像素采样**：开关轨道在「开」态为品牌绿、在「关」态为浅灰。


## 八、付费能力 · 替代侦察（2026-09-27 甘令 · **常规检项，不是临时起意**）

> 甘 09-27 原话：「把寻找替代 api 的方案，列入 skill 雷达检索范围。」并澄清：
> **「skill 雷达」＝ 本管道（skill 仓治理）**；要替代的目标是 **Just One 独有的「账号维度 → 枚举作品 → 取直链」**，
> 不是红狐 —— **红狐费率可接受**，要找的是「能不能覆盖 Just One 那一段」的替代。
> 背景：一次费用审计查出单日异常开销，大头是**重复调用**买同一次结果。

### 为什么是常规检项

「付费接口」一直当背景存在：**没人按「能不能更便宜」重新问过**。它不是被评估过的选择，是默认选项。
一旦出现更便宜的覆盖方式却没人发现，就是** invisible loss**（看不见的漏）。故与 A 集维护捆绑成例行动作。

### 触发（任一命中即开侦察，⛔ 不用等甘点名）

1. 某个付费接口**单日 > ¥20** 或**一周累计 > ¥30**；
2. 出现**重复调用 / 注定失败的调用**（同 id 取链多次、某端点对固定入参恒返空）；
3. **新接一条付费链路前**（先问「有没有现成的更便宜通道」）；
4. 甘点名「XX 太贵 / 找替代」。

⛔ **动手前先查现成资产**（rules/11：解耦优先·先找现成·自搭最后）—— 本机可能早有更便宜通道。
红狐 vs Just One 正是这条规则没执行到位的反面。

### 检索四方向（按性价比排序）

| ① 现有 skill / 脚本里有没有现成通道 | 这活有没有已装 skill 能干 |
|---|---|
| ② 同类接口有没有更便宜的 | 单价 × 调用量，摊到每次 |
| ③ 免费额度 / 免鉴权直链 | 能不能根本不花这笔钱 |
| ④ **开源方案 / 自建** | 现成开源工具能否直接覆盖。⛔ **开源不是禁区**（2026-09-27 甘纠正：「不碰 GitHub」这条描述是错的，本机一直用 git 备份/回滚）；只是要算维护成本，⛔ 别预设「开源一定更省」。 |

### 判据（⛔ 不许只看便宜就换，四关全过才报）

1. **能力覆盖**：新通道是否覆盖旧通道的**全部**能力？红狐便宜但**没有账号维度枚举** ⇒ 是分工，不是替代。
2. **稳定性**：限流 / 登录态 / 反爬 / 封禁风险，失败代价多大。
3. **凭证与合规**：走官方通道，⛔ 禁手搓脚本绕路。
4. **迁移成本**：改几处代码、几份 SOP、几条自动化？能不能回滚（唯一源先备份）。

**产出落点（三处，缺一算没做完）**
1. 本文件 `references/能力集A_默认.md` 对应条目的注释 —— 单价 + 现状；
2. `SOP/` 对应 runbook 的「成本」节 —— 单价表 + 基线；
3. 命中替换 → 走**第④步 SOP 补丁**（`SOP/视频号订阅轮询runbook.md` §四「控成本三条」是现成样例）。

**⛔ 反模式**：不为换而换（没触发条件就主动换＝自加维护成本）；⛔ 不许用「复杂」当价值（高效才是）。

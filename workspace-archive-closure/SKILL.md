# Workspace 物理收口归档工作流

把已退役/已迁移的 workspace 容器移出活跃工作区（`<工作目录>`）到归档落点，不删、可还原，并同步记忆层。

## 触发边界
- 适合：历史沙盒/空壳、已迁移常驻PC 的旧项目容器、计划外探索空间。
- 不适合：活跃使用中的 workspace（如副业工作台）、hub/经验中枢、全局 `.workbuddy` 状态目录。

## 步骤

### 1. 只读扫描（先扫描，绝不先动手）
```bash
ls -1 "<工作区根>"                       # 顶层全量清单
du -sh "<工作区根>"*/                    # 各容器体积
find "<工作区根>" -maxdepth 2 -name ".env"   # 密钥/敏感文件定位（只列路径，不读内容）
```
- 识别隐藏项与 `.DS_Store`；确认全局 `.workbuddy` 等状态目录绝不触碰。

### 2. 漂移检测（关键）
- 对照上次计划/清单（读 HANDOFF/MEMORY 或历史归档清单），列出**计划后新增**的容器。
- 逐项判定：活跃空间（副业/在用）→ 排除；计划后新建但未知 → 默认排除、交用户定。
- 教训：计划会过时，盲按旧清单会误伤活跃空间。

### 3. 与用户确认范围 + 落点
- 用 AskUserQuestion 确认两点：① 精确范围（排除哪些、归档哪些）；② 归档落点（须位于工作区根之外，才能退出活跃列表）。
- 给出推荐默认值；用户授权后再执行（危险动作前显式确认）。

### 4. 外部快照备份
```bash
COPYFILE_DISABLE=1 tar czf "/tmp/<快照名>.tar.gz" "${容器名[@]}"
```
- 快照含 `.env` 仅限本地，绝不上传 IMA/任何传输通道。

### 5. 分批移入（≤10/批）
- `mkdir -p <落点>`；`mv` 每批后核验落点计数递增。
- **移入不删**，守"不删目录留痕"红线。

### 6. 核验
- 落点计数 = 预期归档数；原工作区仅剩 KEEP 项。
- `.env` 红线：确认原工作区已无 `.env` 残留，密钥随容器 relocate、全程未读/未拷/未传。

### 7. 生成归档清单
- 在落点写 `归档清单_<日期>.md`：归档项分类（主业容器/沙盒空壳/新增壳）、排除项、红线核验、还原方式（`mv` 单容器还原 / 解压快照全量还原）。

### 8. 记忆四层同步
- HANDOFF【主线状态】新增节点 + 追加【本session】块。
- 项目 `.workbuddy/memory/MEMORY.md` 补收口记录。
- 当日 `.workbuddy/memory/YYYY-MM-DD.md` 日志（append-only）。

## 红线（不可违反）
1. 不删目录留痕：全程 mv 移入归档，零删除。
2. `.env`/密钥：只 relocate、不读、不拷明文、不进 IMA/runbook。
3. 旧版文档标「弃用」留痕由甘客户端删，CCS 不动删。
4. 扫描发现漂移即停，先确认范围再动手。

## 参考实例
- 2026-08-18：本 workspace 内 15 项迁移期本地备份归档（A 资产包/B 旧版留痕/C 迁移工作文档）。
- 2026-08-19：25 容器（3 主业 + 22 沙盒空壳，含 2 计划后新壳）跨 workspace 移入 `<工作目录>`，排除现役 3 项（hub/副业/公文写作）。

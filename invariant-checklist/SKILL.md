# 不变量清单程式

## 一句话

**问：「如果它真叫这个名字，哪些事必须永远为真？」——答不上来的，就是名字在撒谎。**

把答案写成三条一起交付：**人能读的清单 + 机可跑的红绿检查 + 挂在动作完成处的强制调用**。

## 为什么需要（洞的机制）

「该保护的没保护」不是执行力问题，是**信息形态问题**：

- 用户交出来的是名词（"我要一个素材库"），他脑子里自带一整套常识（库＝不重不漏不丢）——**基本到不需要说出口**；
- 执行方拿到的是需求（需求驱动只做被指定的）；**没被指定的部分，结构上不在视野里**；
- 于是双方都以为对方会说 ⇒ 洞存在且对双方都不可见 ⇒ 只能等叙事矛盾暴露（成本极高）。

**关键**：名词的蕴含**数量有限、可枚举**。所以它是可以显式化的——只是必须有人主动去做，而那个人是执行方。

## 七步

1. **抓名词**。把用户嘴里那个词原样写下来——库、索引、表、池、账、词表、看板、台账、流程，都行。
   **触发靠的是"他递过来一个名词"，不是"他递的是哪个名词"**：换一个词，同一套推导照跑。
2. **推蕴含**。逐条问：「它叫这个名字，哪些事必须永远为真？」推不出来的，就是名字在撒谎。
   - 用**大白话**写句子，不写技术判据（用户判断不了代码，判断得了"库里该不该有两份一样的东西"）。
   - 常见蕴含族：不重 / 不漏 / 不丢 / 可溯 / 可解释 / 受控 / 新鲜 / 同步 / 覆盖 / 对称。
   - 递过来的若是**连线**而不是名词（「把 A 和 B 连起来」），改走下方 **「接缝七族」**
     （「对称」＝其中 **A · 半环** 族）：实测 30 条真洞的落点分布 —— **80% 落在接缝上**，
     段内只占 6 条且清完即止。
3. **给判据**。每条配一个「机可查」的判据（能算出真/假的）。
4. **写检查器**。一个只读脚本：逐条打印 ✅/❗，**红项非零退出码**。
   - 每条红项要能指出**具体是哪些条目**（不是只报个数）。
   - 放在被检查对象旁边，命名固定（如 `check_invariants.py`）。
5. **做负控制**。注入已知缺陷，确认检查器**能红**。只能绿不能红＝假绿。
   - 建议留一个只供测试的入口（如环境变量覆盖输入路径），避免为了测试去污染真数据。
6. **挂触发点**（本程式最关键的一步）。把检查接到「动作完成」处自动跑——比如管道脚本的
   `assemble()` 末尾自动调它。**不靠人记得，是这个程式与"加一条规则"的根本区别。**
   完成判据：**真跑一次那个动作，在它的输出里看见校验结果出红绿**——改完代码不算挂上。
7. **洞现形时归位**。任何一个新洞被发现，当场做两件事：① 加进清单；② 加进检查器。
   ⇒ 洞只现形一次，之后变成护栏；再以别的形状回来，检查器会当场报出。
   **归位时顺手问一句：我这条检查器跳过了什么？**
   护栏的 skip / 豁免规则（「跳过以 `|` 开头的行」「排除备份目录」「只查当日文件」…）会划出
   **无人看守的面**，而那正是同类洞下一次生长的地方 —— 补上它，就是一条新护栏。
   实测（2026-09-24 · 368 容器）：结构闸为避开 markdown 表格而跳过以 `|` 起头的行
   ⇒ 同一份文件里的**对照表**整块无人看守，「改了实体块、漏改对照表」的漂移静默通过。
   推论：**副本漂移的第三种形状 ＝ 同一份文件里的两处**（另两种：两份文件之间 / 决策与原文条之间）。
   它最隐蔽 —— 文件级的「单一真源」检查对它完全无感，只有**面级**判据（这份文件里哪些区域归谁管）能看见。

## 接缝七族（输入是「连线」而不是名词时）

名词问「X 该守什么」；**连线**问「A–B 之间该守什么」—— 这条线就叫 **接缝**。
后者是前者的升维：名词级只能**现形后归位**（洞出现了才知道焊哪条）；
关系级可以**在连线之前就推**（两端是什么已知 ⇒ 线上该守什么可推）。这就是「能预判」的成立条件。

**为什么值得单列**：实测 30 条真洞按落点分 —— **段内 6 / 接缝 24（80%）**。
段内是**枚举型**（表里这几列填齐没有，清完即止，那 6 条至今没再犯）；
接缝是**组合型**（件与件每多一条连线，就多一处可破点）。
接缝洞还有个特点：**要动两件**（写端与读端各一处补丁），不是一件。

24 条接缝洞按**成因**归并 —— 不是 24 种，是 **7 族**：

| 族 | 一句话（含怎么认） |
|---|---|
| **A · 半环** | 有写没读 / 有推没取 / 有进没出 —— 只做半边，而**两边各自的单测都绿** |
| **B · 两侧口径不一致** | 同一字段，两端各按一套语义或格式理解（全称↔简称、两代语义各一套） |
| **C · 输入形状假设** | 进来的东西形状不对，却**静默成功**（不报错、看着全对、结果是错的） |
| **D · 同名两读者两判据** | 同一份东西，两个消费方各写一套解析 |
| **E · 声明 ≠ 实现** | 文档 / 判据 / 字段里说要的，代码没这么做（含「豁免只写在文档里」） |
| **F · 绕开唯一入口** | 没走官方通道、自己写 ⇒ 绕过它的守卫 / 备份 / 序号 |
| **G · 派生件过期** | 真源改了，副本 / 视图 / 复刻件没跟（一份数据两个落点） |

### 三个问题（新接缝产生时逐句问，7 族全覆盖）

1. **这条线上流动的是什么？它由谁唯一持有？另一端是「读它」，还是「也存一份」？** → B / D / G
2. **这条线上有「动作」吗？有的话，它的反向动作在哪？** → A
3. **两端约定的形状与入口，写下来了吗？** → C / E / F

### 硬边界：预判不能替代真跑

那 24 条里有 4 条（同一批）**两端各自的单测全绿**，是端到端跑一遍才现形的。
⇒ 预判的正确用法是「**决定该跑哪条端到端**」，不是「省掉跑」。
7 族只保证**该问的问题问到了**，不保证答对 —— 与「覆盖范围 ＝ 推导者的想象力范围」同一条边界。

## 红线（五条，逐条正面表述）

1. **判据只用等价判定**（全等 / 不等）。不可控的相似度阈值会把护栏变成新洞源——与 2026-09-19 弃用 tfidf 是同一条道理。
2. **检查器只读**。红项一律回官方管道改；在检查器里顺手改数据＝给护栏添第二个写入者。
3. **清单与需求文档并存**。需求说"要什么功能"，清单说"这个名字必须守住的底线"，两份各写各的、互不重叠。
4. **一个名字一份清单**。多个物件挤进一份，判据互相污染。
5. **判据落在结构上，不落在文本 / 存在性上**。「函数在不在」是恒真断言——函数在、但不被调用、
   或被无条件重跑，照样绿。判据要看**调用点的结构**（如按 AST 看这个调用有没有被守卫条件包住）。
   按字面 grep 还有第二重坑：护栏会把源码里**解释自己的注释**判成违规（假红）。
6. **每条判据都要能红，且负控用桩回放**。只绿不红＝假绿，跟假红一样有害（会训练人忽略红灯）。
   验负控 = **在检查器里把退化行为塞成桩**（替换模块函数 / 改 `ROSTER_FILE` 指向临时件），⛔ **不许把被判对象
   的真源文件 cp 成改前那份再跑** —— 2026-09-27 本容器踩过：为验负控换真源、忘恢复，只能靠改动记录重放救回。
   ⛔ 另外盯「恒等式判据」：若某判据的前提是"数据只增不减/每行迟早被认到"，那它对任何历史数据都恒绿，
   读不出"还剩什么没干"（实例：`intake --all` 报「待处理 0」）。这种要把判据换成**集合差**（计划集合 − 已办集合），
   比成员、不比数量。

## 边界（必须对用户说清）

- **不适用**：纯创意产出（写作 / 设计 / 策略，说不出"必须永远为真"的底线）；一次性脚本；需求明确且无长期维护负担的场合。
- **覆盖范围＝推导者的想象力范围**。推不出的那条治不了，只能靠用户的探针 + 时间。
- 所以别承诺"不会再有洞"；正确说法是：**洞只现形一次，之后可测**。
- **逐个长**：一次只推当前这个物件的清单；其余的在各自的洞现形时归位——**归位就是它的生长机制**。

# 收尾清算

> **一句话**：收尾不是写简报就完事 —— 凡本 session 对待决待办给出了确定性答案，当轮就把过程信息删掉，不留「已修正 / 已作废」的批注痕迹。

## 何时用

- 用户说「收尾」→ 在原 5 段式（目标 / 决定 / 规则 / 状态 / 下一步）的**「决定」之后插入本清单**。
- 本 session 出现待办被关闭 / 完成 / 消解 / 迭代 → 即便用户没说收尾，也跑本清单。

## 硬约束（违反即错）

1. **删除 ＝ 外移，永不 rm**。正文删掉的内容先落到 `记忆外移/<目录>/`，可回查可回退。
2. **E3 只提示不删**。CCS 推断出来的结论（如 grep 零匹配）不自动清算，回报里单列等一句话。
3. **制度性条目豁免**：宪法 / lane / CC 标记 / 转写识别环 / SOP 地图 / 凭证路径，不因日期老而清。
4. **单次清算 ≤5 项**；超过说明积压，单独出表交甘，不硬清。⚠️ **此限只针对「终态清算项」**（待办走到关闭/完成/消解/迭代）；**「体量治理」不适用** —— 它是一次性压到目标值，改动处数可远超 5（2026-09-25 实例：MEMORY 一轮 34 处替换 ⇒ 7863→6998）。两者混为一谈会误判「积压」。

## 清算判据（真源 · 自本 skill v1.3.0 起）

**四类终态**：

| 终态 | 含义 | 删除范围 |
|---|---|---|
| 关闭 | 不做了 | 待办行 + 相关过程段全删 |
| 完成 | 做完了 | 删过程段，留一行结果 |
| 消解 | 被别的事吸收 / 失效 | 删条目，留指向新载体的指针 |
| 迭代 | 升级为新形态 | 删旧表述，新表述入位（最危险） |

**证据分级（防替他判断）**：

| 级别 | 判据 | 动作 |
|---|---|---|
| E1 | 甘原话拍板 | 自动清算 |
| E2 | 文件已落结果（待办表已填 / 产出物已生成） | 自动清算 |
| E3 | CCS 推断或代码事实（如 grep 零匹配） | **只提示，不自动删**，等一句话 |
| E0 | 无证据 | 不动 |

**档案命名规范**（14/21 天规则，以记录日期计）：

| 未引用时长 | 处置 | 命名规范 |
|---|---|---|
| ≥14 天（<21 天） | 移出记忆区 + 正文留指针 | `记忆外移/近期记忆外移_<清理日期>/` |
| ≥21 天 | 归档移除，正文查不到时翻档案 | `记忆外移/<截止日期>前记忆_<清理日期>移除/` |

**目录适配（跨容器）**：只钉死归档子目录命名格式，外层目录名以各容器既有为准，不强制全机同名。

## 清算六步（逐项勾选，回报时打出勾选结果）

> **先跑一次护栏取基线**：动笔前先实跑本容器护栏 / 闸门（本容器：`编排脑/项目闸门.py gate` ＋ `check_steady_invariants.py` ＋ `board`）—— **收尾报告与记录里的每个数字都来自这次实跑，禁凭记忆写数**。清算后再跑一次对比（见第 5 步）。
> 2026-09-24 的由来：收尾写记录时若凭记忆填「红绿 26/26」「三色第二色 6」，一旦某条已被本轮关掉（如 OI-20），报告就当场失真 —— **一个数错，整份交接不可信**。

- [ ] **1 · 列终态**：本 session 有哪些待办/议题走到了 关闭 / 完成 / 消解 / 迭代？逐项列出。
- [ ] **2 · 定证据**：每项标 E1（甘原话）/ E2（文件已落结果）/ E3（CCS 推断）/ E0（无证据）。**E3、E0 到此为止，只提示不动手。**
- [ ] **3 · 定位过程段**：在 `HANDOFF.md`、`.workbuddy/memory/MEMORY.md`、当日日志里定位对应过程叙述。**必查 `HANDOFF.md`【本session】里历史收尾段的「下一步」行**——任务一旦做完，这些指令就变成过期指令，是最容易漏删的一类（2026-09-23 实例：三条「下一步：进某项目剩余 7 条」残留于 21:2x / 22:1x / 22:2x 段）。
- [ ] **4 · 浓缩一行**：把过程段压成一行裁决态 / 结果态 / 指针（不是摘要，是结论）。**写完当场自查一句**：不许出现「原／曾／已修正／已作废／系误」这类**追溯词** —— 那就是批注式修改（`rules/13` §2 铁律 1）。把错的地方直接写成对的，不留痕迹。
  > 2026-09-24 实例：更正 OI-22 的过期归因（原写「属 M2」）时首写用了 `~~删除线~~` ＋ 「原记…系误」，当轮即改回纯裁决态。**这类错误发生在「我在做修正」的语境里，最不设防。**
- [ ] **5 · 外移 + 删除**：原文 `mv` 到 `记忆外移/` 对应目录（≥21 天用 `<截止日期>前记忆_<清理日期>移除/`，14–21 天用 `近期记忆外移_<清理日期>/`），正文删净，不留批注。
  > ⚠️ **删前先问：护栏靠什么字符串判定？** 本容器的护栏有**按字样判**的 —— `check_steady_invariants` **V8** 要求 `X-1…X-11` 都出现在 STATE 正文；**V4** 要求每个开放项在计划树有认领。清算把过程文本删净时，会把这些字样**一起删掉** ⇒ **护栏转红不是误报，是它拦住了「清算把信息删过头」**。
  > ⇒ **清算后必复跑护栏**（`编排脑/check_steady_invariants.py` ＋ `编排脑/项目闸门.py gate`）；红了就把该保留的字样以**紧凑台账**形式留在正文，不要回退清算。
  > 2026-09-24 实例：把 `OI-22/23/24` 的 evidence 压成一行后，**V8 报缺 `X-2/X-3/X-7/X-9`** ⇒ 补一行「走查洞 X 台账」回状态文件（STATE 30357 → 26100 字符，仍净省 4.2k）。
- [ ] **6 · 标 closed**：待办表对应行标 closed 并写日期；已被别的事吸收的，留指向新载体的指针。

## 并发写入防护（多会话同 workspace · 2026-09-24 增）

同一天可能有 **2–3 个 session 并发写同一批文件**（`HANDOFF.md` / `MEMORY.md` / 当日日志 / `STATE`）。2026-09-24 实测：本 session 收尾期间，另一 session 正往 `MEMORY.md` **追加**一条新裁决。⇒ 压缩 / 追加前必做三件：

1. **走唯一写入通道（首选）**：若容器已把共享件写入收成唯一通道 —— 本容器 STATE ＝ `编排脑/state_io.py`、其余共享件 ＝ `编排脑/shared_io.py` 的 `patch/append/write` —— **一律走它**（自带 per-file 锁 ＋ 写前重读 CAS ＋ 备份轮转 ＋ 原子替换）。**不要为压缩另造脚本**：自造的就是第二份没人验的实现，正是 V22「一副规矩两个副本」。
   无此类通道时，才按下面的手工工序自带：**写前重读 CAS** —— 把「读入时的内容」与「落盘前重读的内容」比对，**不一致即中止不写**，重取最新再做。
   > 2026-09-24 实例：本 session 收尾对 `MEMORY.md` 做了 36 次改动（三轮瘦身 ＋ HANDOFF/日志），全部走 `shared_io`，备份自动轮转、零冲突。
2. **别拿「别人刚写的段落」当 Edit 锚点** —— 替换式锚点会**连邻近要保留的行一起删掉**。2026-09-24 实例：用另一 session 刚写的段末两行作锚点做追加，**误删其中一行**（当场发现并回补）。⇒ **追加只在文件末尾做，锚点取「自己刚写的内容」**。
3. **压缩后复检关键串**：`grep` 自己写入的标记串（新增的不变量编号、结论行、版本号），确认没被并发覆盖。

## 收尾附加步 · 日期扫描（「自然滑出」的执行点）

用户已定：记忆区剩余日志**不做一次性清理，等自然滑出阈值**。这意味着**每次收尾必须扫一次日期**，否则没人执行归档：

```bash
cd "<workspace>" && ls .workbuddy/memory/ && date +%Y-%m-%d
```

对每个日志算天数（以记录日期为准）：
- ≥21 天 → `记忆外移/<截止日期>前记忆_<今日>移除/`（正文不留指针，查不到去翻档案）
- ≥14 天且 <21 天 → `记忆外移/近期记忆外移_<今日>/`（正文留一行指针）
- <14 天 → 不动

扫完补一次 `00_索引.md`（归档口径 + 清单 + 回查方法）。

## 收尾附加步 · 决策点提前登记（防「一收尾又冒出来」）

> 甘 2026-09-23 原话：「确定没有其他决策点了？别我一收尾，你又冒出几个来。」
> 根因＝决策点**没在预见到的当下登记**，攒到收尾那刻才第一次抛出。**本步把它挂到「收尾」这个已有触发点上。**

**判别式 —— 命中任一即必须提前登记为 `deferred` + 写死 `unblock_cond`，禁止攒到收尾才提：**

1. 要花钱（API 调用 / 按量计费 / 订阅）
2. 要动或删文件（含归档移动）
3. 要新增常驻任务（automation / 常驻服务 / 新端口）
4. 存在两个以上载体可能漂移（如待办表 vs 状态文件双写）
5. 属**设计选择**而非缺陷修复（缺陷修复由 CCS 自拍即可）

**注意 · 花钱 ≠ 一律 deferred**：命中判别式①（要花钱）时**登记是必须的**，但**状态词看语义** —— 若甘已排定「先备料 → 回报 → 再由我发令」的次序，那属于**卡在外部输入** ⇒ 用 `挂起` ＋ 把金额与解法写进 `unblock_cond`（2026-09-23 实例：OI-21「7 条 ASR 待发令 ≈¥0.84」）；只有「等甘拍板、且他没排过次序」才用 `deferred` + `kind: decision`。

**注意 · 多会话并发**：同 workspace 可能多 session 同时写同一批文件。收尾时若发现【本session】写的是**另一条线**的事，**不要整体重写** —— 改成分线并列（A 线 / B 线），把自己的线补进去。**压缩 / 追加的具体防护（写前重读 CAS、锚点选择、复检关键串）→ 见上「并发写入防护」节**；并发风险本身登记为开放项（2026-09-23 实例：OI-20）。

**不命中 → CCS 自拍**：写进该条目的 `evidence` 字段并注明「CCS 自拍，甘可推翻」，**不占甘的注意力**。

**收尾时执行**：扫一遍本 session 碰过的规划件 / 状态文件 / 开放项表，确认没有「未登记但执行到某步必然要拍」的点；有则当场登记，并在回报里单列「本轮提前登记 N 项」。

**反例（2026-09-23）**：项目代码化收尾时，卡点 1/4 已登记但「A1 跑真数据要花钱」「9 个调试件归档」「新建 automation」「残留 mp4 删不删」四点**全部未登记**——它们不在当时的 4 卡点表里，却每一步都会拦人。补登记为 OI-11～OI-15 后才收敛。

## 体量自检（收尾尾声顺手做）

```bash
wc -m .workbuddy/memory/MEMORY.md .workbuddy/memory/*.md | tail -3
```

- 项目级 MEMORY ≤8000 字符（目标 ≤6000，留 25% 余量）；超了按重写三铁律压。
- 注意：体量一律用 **字符数**（`wc -m`），不用行数、不用字节。
- **怎么压**：一律走容器唯一通道 `shared_io.patch(path, fn)`（自带 per-file 锁 ＋ 写前重读 CAS ＋ 备份轮转）；替换对用 `python3 -c` 或**临时脚本**调用，**用完即删**（⛔ 不自造压缩实现 —— 那就是 V22「一副规矩两个副本」）。**压完必复跑护栏**：parity 的 P2「不丢」**按字样判**，删到关键串会转红 ⇒ 把字样留下、不回退压缩。
- **压不到位就别硬压**：若余下**全是裁决态**，压到目标值＝删裁决 ⇒ **停在有真实余量处即可**，并在报告里写明「未达 X，原因＝余下皆裁决态」（2026-09-25 实例：7863→6998，余量 137→1002，6000 未达）。

## 回报格式

在 5 段式简报后追加一段：

```
【本轮清算 N 项】
- <事项> · <终态> · <证据级> · 删了什么 / 留了一行什么 / 外移到哪
- <提示不删>：<事项> · E3 · 待你一句话
【日期扫描】记忆区剩 N 个日志，本次滑出 M 个 → <归档目录>
```

没得清就写「本轮无清算项」—— 不要为了凑数清。

## 已知边界

- 本 skill **不解决触发问题**，只解决「步骤不漏」。触发源仍是「人说收尾」这个人在环事件（平台未见 hook 机制）。人不说收尾就走 → 只能靠周一自动化兜底。
- 与 `injection-layer-governance`（装机伴侣）分工：那个管**槽位与体量体检**，这个管**收尾时刻的删除动作**；清算判据在本文件，写文件纪律在 rules/13，不各存一份。

# SKILL.md - koubo-diff-resolver（修改自动识别器）

> **职责**：消除"用户改完贴回，agent 却要追问改了哪"的摩擦。
> **适用**：004 口播 / 005 公众号 的「方式二：粘贴回来」场景。
> **用户画像**：非技术同事/商用客户，不会主动说明修改点，只期望贴回后 agent 自动识别。

---

## 一、何时调用

| 场景 | 是否调用 |
|------|---------|
| 用户发回修改意见（"第二段删掉"）| ❌ 不调用，按意见直接改 |
| 用户贴回一段文本（疑似改后版）| ✅ 调用，自动 diff |
| 用户说"我改好了，贴回给你" | ✅ 调用 |
| 用户说"整体OK，不用改" | ❌ 不调用，直接进终稿 |

**判断依据**：当前 Session 是否已有「草稿原文」（Step 6 输出的 Layer 1 草稿）？
- 有 → 用户贴回的是修改版 → 自动 diff
- 无 → 用户贴回的是新稿 → 询问：这是新稿还是修改？

---

## 二、调用方式

### 方式A：stdin（推荐，零临时文件）

把「草稿原文」和「用户贴回文本」用单独一行的 `=====` 分隔，通过 stdin 传入：

```bash
cat << 'EOF' | python3 ~/.workbuddy/skills/koubo-diff-resolver/diff_resolve.py
<此处粘贴 Step 6 输出的草稿原文>

=====

<此处粘贴用户贴回的修改版文本>
EOF
```

### 方式B：文件（原文/改后版已落盘时）

```bash
python3 ~/.workbuddy/skills/koubo-diff-resolver/diff_resolve.py \
  /path/to/original.md \
  /path/to/modified.md
```

---

## 三、输出格式

脚本输出结构化变更，agent 直接据此更新终稿：

```
【删除】
<被删除的段落/句子>

【新增】
<新增的段落/句子>

【修改】
原:
<原内容>
新:
<新内容>
```

若无变更，输出：`【无变更】原文与修改版一致`

---

## 四、agent 后续动作（集成方负责）

diff 结果出来后，004/005 应：

1. 向用户展示变更摘要（用户可见，确认 agent 理解正确）：
   ```
   ✅ 已识别你的修改：
   · 删除了第2段关于XXX的描述
   · 第3段"XXX"改为"YYY"
   · 新增了结尾转化句
   ```
2. 根据变更更新终稿全文
3. 输出修改后的完整草稿
4. **若 diff 结果含无 reference 的 claim（⚠️ 项）**：
   → 在草稿下方追加「⚠️ 请确认」提示框
   → 明确告知用户：「确认后回复『可以』，我写 L5」
5. **若 diff 无 ⚠️ 项**：直接等用户「可以」→ 进 Step 8

---

## 五、容错

| 情况 | 处理 |
|------|------|
| Session 原文被 compaction 压缩，提取不全 | 从 L5 拉原始稿（需关联 L5 ID）；若无 L5，请用户重发原文 |
| diff 结果为「无变更」但用户说改了 | 请用户确认是否贴错了版本 |
| 用户贴回文本与原文差异极大（疑似全新稿）| 询问：这是新稿还是基于草稿的大改？|

---

## 六、设计原则

- **零负担**：用户不需要说"我改了第X段"，agent 自动识别
- **可视化**：变更摘要给用户看，建立信任（用户知道 agent 理解正确）
- **复用**：004/005 共用
- **轻量**：仅依赖 Python 标准库 difflib，无外部依赖
